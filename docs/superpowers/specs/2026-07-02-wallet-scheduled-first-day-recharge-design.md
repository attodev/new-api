# 정기충전 매월 1일 정책 설계

## 목표

정기충전을 사용자에게 더 직관적인 월별 충전 흐름으로 단순화한다. 일반 사용자에게는 "매달 1일에 다음 금액만큼 자동 충전"되는 월별 정기충전만 노출하고, 테스트를 위한 사용자 지정 주기는 관리자 화면에만 남긴다.

## 범위

- 월별 정기충전의 실제 다음 충전 시각 계산은 백엔드에서 매월 1일 00:00 기준으로 변경한다.
- 사용자 지갑 화면에서는 정기충전 주기 선택 UI를 제거하고 월별 프리셋 금액만 선택하게 한다.
- 관리자 자동충전 프리셋 화면에서는 정기충전 주기 추가 버튼을 월별과 테스트용 주기 두 개로 제한한다.
- 테스트용 주기는 하나만 존재할 수 있게 FE에서 제한한다. 이미 테스트용 주기가 있으면 기존 값을 삭제해야 새 테스트용 주기를 추가할 수 있다.
- 일별, 주별 정기충전은 새 UI에서 만들거나 선택할 수 없게 숨긴다. 기존 DB/API 스키마와 프리셋 API 계약은 유지한다.

## 백엔드 동작

월별 정기충전(`interval_unit = "month"`)은 기존의 "기준 시각 + N개월" 계산 대신 다음 월별 앵커를 사용한다.

- 기준 시각 이후에 도래하는 다음 1일 00:00을 다음 충전 시각으로 잡는다.
- 예를 들어 6월 30일에 등록하면 7월 1일 00:00이 다음 충전 시각이고, 7월 1일 00:00 충전이 끝난 뒤에는 8월 1일 00:00이 다음 충전 시각이다.
- 충전 성공 후에도 기존 `next_charge_time` 기준으로 다음 1일을 계산한다.
- `interval_unit = "custom"`은 테스트용이므로 기존 `custom_seconds` 기반 계산을 유지한다.
- 월별 정기충전은 카드 등록 직후 즉시 충전 플래그를 무시한다. 테스트용 custom은 기존 즉시 충전 동작을 유지한다.

시간대는 기존 코드의 `time.Time` 흐름을 따라 서버 로컬 시간 기준으로 처리한다.

## 사용자 UI

사용자 지갑의 정기충전 카드에서 주기 선택 버튼을 제거한다. 월별 프리셋만 필터링해 보여주고, 본문에는 "매달 1일에 다음 금액만큼 자동 충전" 메시지와 금액 선택 버튼만 표시한다.

활성 정기충전 정책이 월별이면 현재 정책 설명도 "매달 1일"로 표시한다. 비월별 기존 정책이 남아 있을 가능성은 고려해, 월별이 아닌 경우에는 기존 interval 표시를 보조적으로 유지한다.

## 관리자 UI

관리자 자동충전 프리셋의 정기충전 옵션에서 다음만 제공한다.

- 월별 추가
- 테스트용 주기 추가

테스트용 주기는 `interval_unit = "custom"` 프리셋 그룹으로 저장하고, 화면에서는 "테스트용 주기"로 표시한다. 테스트용 주기 그룹이 이미 있으면 추가 버튼은 비활성화한다. 테스트용 주기 초 단위 입력은 기존처럼 해당 그룹에서 수정할 수 있다.

월별 그룹은 충전 금액 여러 개를 계속 지원한다. 테스트용 주기도 하나의 주기 그룹 안에서는 테스트 금액 목록을 관리할 수 있다.

## 테스트

- Go 모델 테스트로 월별 next charge가 매월 1일 00:00으로 계산되는지 검증한다.
- Go 모델 테스트로 월별 정기충전은 카드 등록 직후 즉시 충전되지 않는지 검증한다.
- React 테스트로 사용자 정기충전 UI가 주기 선택을 숨기고 월별 안내 문구와 금액 버튼만 렌더링하는지 검증한다.
- React 테스트로 관리자 UI 헬퍼가 일/주 프리셋을 새 옵션 상태에서 제외하고, 테스트용 주기를 하나로 제한하는지 검증한다.
