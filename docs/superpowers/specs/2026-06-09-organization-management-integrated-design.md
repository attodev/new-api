# 조직 관리 및 조직 구독 통합 설계서

## 1. 목적

이 문서는 조직 관리 기능과 이후 확장된 조직 지갑, 조직 사용량 모니터링, 조직 전용 구독 플랜 기능을 하나의 기준 설계로 통합한다.

기존에는 기능별 설계서가 여러 문서로 나뉘어 있었고, 일부 변경은 구현 과정에서 바로 반영되었다. 이 문서는 현재까지 합의 및 구현된 요구 조건을 한곳에 정리해 이후 개발, 테스트, 운영 판단의 기준으로 사용한다.

## 2. 배경

시스템의 기존 사용자 권한은 전역 `User.Role` 중심이다.

- 일반 사용자: `RoleCommonUser = 1`
- 관리자: `RoleAdminUser = 10`
- 수퍼 관리자: `RoleRootUser = 100`

기존 `User.Group`은 조직이나 팀을 의미하지 않는다. 이 값은 모델 접근, 채널 사용 가능 여부, 그룹별 과금 배율, 충전 배율, 토큰 그룹 선택, 전역 구독 업그레이드, 로그, 성능 지표에 이미 사용된다.

따라서 조직 기능은 `Group`을 재사용하지 않고 별도 조직 필드와 조직 역할로 구성한다.

## 3. 핵심 요구사항

조직 기능의 핵심 요구사항은 다음과 같다.

- 사용자는 하나의 조직에만 소속될 수 있다.
- 조직 역할은 `member`, `admin`, `owner` 세 가지다.
- 조직 역할은 전역 관리자 권한과 분리한다.
- 조직 소유자와 조직 관리자는 자기 조직 사용자만 관리할 수 있다.
- 전체 관리자는 조직 생성, 조직 quota 조정, 조직별 사용량 조회, 조직별 구독 관리를 할 수 있다.
- 조직 일반 사용자는 조직 관리 기능을 사용할 수 없다.
- 조직 사용자의 실제 사용 금액은 조직 quota 지갑에서 최종 차감한다.
- 조직 사용자는 기존 quota 방식과 조직 구독 플랜 방식 중 하나로 운영될 수 있다.
- 조직 구독 플랜은 조직 내부 전용 정책이며, 사용자가 직접 구매하거나 변경할 수 없다.
- 조직 구독 플랜 사용자는 개인 지갑 잔액을 직접 관리하지 않는다.
- 문서와 주요 UI 문구는 한국어를 포함한 i18n 키로 관리한다.

## 4. 비목표

이번 범위에서 제외하는 항목은 다음과 같다.

- 기존 전역 관리자 권한 체계를 범용 RBAC로 대체하지 않는다.
- 다중 조직 멤버십은 지원하지 않는다.
- 조직 사용자가 직접 조직을 생성하는 셀프서비스 기능은 포함하지 않는다.
- 조직 구독 플랜의 결제 기능은 포함하지 않는다.
- 조직 구독 플랜을 기존 전역 구독 플랜과 같은 테이블로 합치지 않는다.
- 조직 관리자에게 채널, 모델 가격, 결제 설정, 시스템 설정 권한을 부여하지 않는다.

## 5. 권한 설계

### 5.1 전역 권한

전역 권한은 기존 `User.Role`을 유지한다.

- 수퍼 관리자는 모든 조직을 생성하고 관리할 수 있다.
- 일반 관리자 권한은 기존 관리자 기능에 사용되며, 조직 역할과 자동으로 연결되지 않는다.
- 조직 관리자 또는 조직 소유자라도 전역 `Role`이 낮으면 전역 관리자 화면에 접근할 수 없다.

### 5.2 조직 권한

조직 역할은 `User.OrganizationRole`로 관리한다.

- `member`: 조직 일반 사용자
- `admin`: 조직 사용자, quota, 사용량, 조직 구독을 관리할 수 있는 조직 관리자
- `owner`: 조직 소유자. 조직 관리자의 권한에 더해 조직 구성원 추가와 역할 관리가 가능하다.

조직 관리자와 조직 소유자는 다음 작업을 할 수 있다.

- 자기 조직 사용자 목록 조회
- 자기 조직 사용자 활성화/비활성화
- 자기 조직 사용자 quota 조정
- 자기 조직 사용량 대시보드 조회
- 자기 조직 사용 로그 및 작업 로그 조회
- 자기 조직 전용 구독 플랜 생성, 수정, 비활성화
- 자기 조직 사용자에게 구독 플랜 할당, 변경, 취소

조직 소유자는 추가로 다음 작업을 할 수 있다.

- 조직에 사용자 추가
- 조직 내 사용자 역할 변경

조직 관리자와 소유자는 다음 작업을 할 수 없다.

- 전역 `User.Role` 변경
- 기존 `User.Group` 직접 변경
- 전역 관리자 또는 수퍼 관리자 관리
- 비밀번호 초기화
- 채널, 모델 가격, 결제, 시스템 설정 변경

## 6. 데이터 모델

### 6.1 Organization

조직은 별도 `organizations` 테이블로 관리한다.

주요 필드:

- `id`
- `name`
- `description`
- `owner_user_id`
- `status`
- `quota`
- `used_quota`
- `created_at`
- `updated_at`

`quota`는 전체 관리자로부터 확보한 조직 선불 지갑 잔액이다. `used_quota`는 조직 전체 누적 사용량이다.

### 6.2 User 조직 필드

사용자 모델에는 조직 소속 정보를 추가한다.

- `organization_id`
- `organization_role`

`group`은 기존 의미를 유지한다.

### 6.3 OrganizationSubscriptionPlan

조직 전용 구독 플랜이다. 전역 구독 플랜과 분리된 조직 내부 정책이다.

주요 필드:

- `id`
- `organization_id`
- `title`
- `subtitle`
- `duration_unit`
- `duration_value`
- `custom_seconds`
- `total_amount`
- `enabled`
- `sort_order`
- `created_at`
- `updated_at`

현재 UI에서는 불필요한 복잡도를 줄이기 위해 다음 항목은 사용자가 직접 설정하지 않는다.

- quota reset 별도 설정
- reset custom seconds 별도 설정
- upgrade group

구독 사용량 리셋 주기는 플랜 기간과 동일하게 동작한다.

### 6.4 OrganizationUserSubscription

조직 사용자에게 할당된 실제 구독 인스턴스다.

주요 필드:

- `id`
- `organization_id`
- `user_id`
- `plan_id`
- `amount_total`
- `amount_used`
- `start_time`
- `end_time`
- `status`
- `last_reset_time`
- `next_reset_time`
- `assigned_by_user_id`
- `created_at`
- `updated_at`

상태:

- `active`
- `cancelled`
- `expired`

정책상 한 사용자는 동시에 하나의 활성 조직 구독만 가진다. 새 플랜을 할당하면 해당 사용자에게 남아 있던 모든 `active` 조직 구독을 먼저 취소한 뒤 새 구독을 생성한다.

## 7. 조직 quota 및 과금 설계

### 7.1 조직이 없는 사용자

조직이 없는 일반 사용자는 기존과 동일하게 본인 quota에서 사용량이 차감된다.

### 7.2 조직 사용자 - 일반 quota 방식

활성 조직 구독이 없는 조직 사용자는 기존 조직 quota 방식으로 동작한다.

검증:

- 사용자 quota가 충분해야 한다.
- 조직 quota가 충분해야 한다.

차감:

- 사용자 quota를 차감한다.
- 조직 quota를 차감한다.
- 사용자 `used_quota`를 증가시킨다.
- 조직 `used_quota`를 증가시킨다.
- 사용 로그의 `user_id`는 실제 요청 사용자를 유지한다.

### 7.3 조직 사용자 - 조직 구독 방식

활성 조직 구독이 있는 사용자는 개인 quota 잔액 대신 조직 구독 한도를 사용자별 사용 한도로 사용한다.

검증:

- 조직 구독의 남은 한도가 충분해야 한다.
- 조직 quota가 충분해야 한다.

차감:

- 조직 구독의 `amount_used`를 증가시킨다.
- 조직 quota를 차감한다.
- 사용자 `used_quota`를 증가시킨다.
- 조직 `used_quota`를 증가시킨다.

중요 정책:

- 조직 구독이 활성 상태이면 사용자 quota로 fallback하지 않는다.
- 조직 구독 한도가 부족하면 사용자 quota가 남아 있어도 요청은 실패한다.
- 조직 quota가 부족하면 조직 구독 한도가 남아 있어도 요청은 실패한다.
- 조직 구독 사용자는 개인 지갑에서 직접 충전하지 않는다.

### 7.4 정산 및 환불

선차감 후 실제 사용량이 달라지면 정산 단계에서 차액을 반영한다.

- 일반 조직 quota 방식: 사용자 quota와 조직 quota를 함께 조정한다.
- 조직 구독 방식: 조직 구독 사용량과 조직 quota를 함께 조정한다.
- 요청 실패 또는 환불 시 선차감된 값을 되돌린다.

## 8. 조직 구독 자동 갱신

조직 구독은 플랜 기간을 기준으로 자동 갱신된다.

- `status = active`인 구독은 갱신 대상이다.
- 만료 시간이 지났더라도 active 상태이면 다음 요청 또는 활성 구독 조회 시 갱신될 수 있다.
- 갱신 시 새 기간이 계산되고 `amount_used`는 새 기간 기준으로 초기화된다.
- cancelled 상태는 갱신되지 않는다.

삭제 또는 취소 동작은 만료 시간과 무관하게 해당 사용자에게 남아 있는 모든 active 구독을 취소해야 한다. 그래야 만료되었지만 갱신 대상인 active 구독이 중복 할당의 원인이 되지 않는다.

## 9. API 설계

### 9.1 조직 관리

대표 API:

- `GET /api/organizations`
- `POST /api/organizations`
- `PATCH /api/organizations/:id`
- `GET /api/organization/profile`
- `GET /api/organization/users`
- `PATCH /api/organization/users/:id`
- `PUT /api/organization/users/:id/membership`
- `GET /api/organization/assignable-users`

전체 관리자는 조직 생성과 조직 quota 조정을 수행한다. 조직 소유자와 관리자는 자기 조직 기준으로 사용자 관리 API를 사용한다.

### 9.2 조직 지갑

대표 API:

- `GET /api/organization/profile`
- 조직 결제 provider별 payment 요청 API

조직 소유자는 개인 지갑 대신 조직 지갑을 충전하는 흐름을 사용한다. 조직 일반 사용자는 지갑에서 충전 동작을 볼 수 없고, 조직에서 할당한 quota 또는 조직 구독 상태만 확인한다.

### 9.3 조직 대시보드와 로그

대표 API:

- `GET /api/organization/dashboard`
- `GET /api/organization/usage-logs`
- `GET /api/organization/task-logs`

조직 소유자와 관리자는 조직 범위로 제한된 사용량과 로그를 볼 수 있다. 전체 관리자는 조직 선택 기능을 통해 특정 조직의 동일 화면을 조회할 수 있다.

조직 선택 값은 브라우저에 저장하여 대시보드, 사용 로그, 작업 로그 사이를 이동해도 마지막으로 선택한 조직을 유지한다.

### 9.4 조직 구독

대표 API:

- `GET /api/organization/subscription/plans`
- `POST /api/organization/subscription/plans`
- `PATCH /api/organization/subscription/plans/:id`
- `DELETE /api/organization/subscription/plans/:id`
- `GET /api/organization/subscription/users`
- `PUT /api/organization/subscription/users/:user_id`
- `DELETE /api/organization/subscription/users/:user_id`
- `GET /api/organization/subscription/self`

전체 관리자는 `organization_id` query를 사용해 대상 조직을 선택한다. 조직 소유자와 관리자는 자기 조직으로 자동 제한된다.

## 10. 프론트엔드 설계

### 10.1 메뉴

조직 소유자와 조직 관리자에게 조직 메뉴를 제공한다.

- 조직 사용자
- 조직 대시보드
- 조직 사용 로그
- 조직 작업 로그
- 조직 구독

전체 관리자에게도 조직 대시보드, 조직 사용 로그, 조직 작업 로그, 조직 구독 메뉴를 제공한다. 전체 관리자 화면에는 조직 선택 드롭다운이 추가된다.

조직 일반 사용자에게는 관리 메뉴를 숨긴다.

### 10.2 조직 사용자 화면

조직 사용자 화면은 다음 기능을 제공한다.

- 조직 사용자 목록 조회
- 사용자 상태 변경
- 사용자 조직 역할 표시 및 변경
- 조직 quota 잔액과 사용량 표시
- 조직 quota 조정
- 사용자 quota 조정

조직 구독 플랜이 활성화된 사용자는 개인 quota 잔액을 직접 조정하지 않는다.

- 현재 quota 잔액은 `0 (조직 플랜 사용 중)`으로 표시한다.
- quota 입력칸은 비활성화한다.
- 빠른 quota 버튼도 비활성화한다.
- 저장 로직도 active 구독 사용자에 대해서는 quota 변경을 무시한다.

### 10.3 조직 지갑 화면

조직 소유자는 개인 지갑 대신 조직 지갑을 충전한다. 조직 일반 사용자는 지갑 화면에서 충전 기능 없이 자기 사용 상태만 확인한다.

조직 구독 플랜에 속한 사용자는 지갑의 현재 잔액 카드에서 실제 개인 quota 잔액을 보지 않는다.

- 잔액 값: `조직 플랜 사용 중`
- 설명: `잔액은 할당된 조직 플랜으로 관리됩니다`
- 사용량과 요청 수는 그대로 표시한다.
- 사용자 그룹 badge의 `default`는 한국어에서 `기본값`으로 표시한다.

### 10.4 조직 구독 화면

조직 구독 화면은 다음 영역으로 구성된다.

- 플랜 생성/수정 폼
- 조직 플랜 목록
- 사용자별 플랜 할당 영역
- 현재 할당된 사용자 목록

플랜 생성/수정 폼:

- 첫 줄: 제목, 부제목, 생성/저장 버튼
- 두 번째 줄: 금액, 기간, 사용자 지정 초
- 사용자 지정 초는 기간이 `custom`일 때만 활성화한다.
- quota reset, reset custom seconds, upgrade group은 UI에서 제거한다.

플랜 목록:

- 금액
- 기간
- 상태 대신 필요한 경우 비활성화된 플랜 표시
- 재설정 문구 대신 기간을 보여준다.

사용자별 플랜 할당:

- active 플랜이 있는 사용자는 새 할당 대상 드롭다운에서 제외한다.
- 할당 성공 후 선택한 사용자와 플랜 값을 초기화한다.
- 취소된 구독은 기본 할당 목록에서 숨긴다.
- 삭제/취소는 해당 사용자에게 남아 있는 모든 active 구독을 취소한다.

## 11. 조직 대시보드 설계

조직 대시보드는 조직 운영자가 조직 사용량을 한눈에 확인하기 위한 화면이다.

기본 기간:

- 오늘
- 최근 7일
- 최근 30일
- 사용자 지정 기간

요약 카드:

- 조직 quota
- 조직 사용량
- 기간 내 사용량
- 기간 내 요청 수

차트와 표:

- 날짜별 사용량 추이
- 사용자별 사용량 차트
- 모델별 사용량 차트
- Top 사용자
- Top 모델

조직 대시보드의 그래프는 관리자 대시보드의 차트 패턴을 참고해 `VChart` 기반으로 구성한다. 조직별 사용자/모델 집계는 조직 사용자 ID 범위 안의 로그만 포함한다.

## 12. 로그 설계

조직 사용 로그와 작업 로그는 조직 범위로 제한한다.

- 조직 소유자와 관리자는 자기 조직 사용자의 로그만 볼 수 있다.
- 전체 관리자는 선택한 조직의 로그를 볼 수 있다.
- 조직 밖 사용자의 로그는 포함하지 않는다.
- 조직 구독으로 사용한 요청은 로그 상세에 조직 구독 관련 정보를 포함한다.

로그에 포함할 수 있는 조직 구독 정보:

- `organization_subscription_id`
- `organization_subscription_plan_id`
- `organization_subscription_plan_title`
- `organization_subscription_amount_total`
- `organization_subscription_amount_used_after_pre_consume`

## 13. 에러 처리

주요 에러 정책은 다음과 같다.

- 조직 quota 부족: 조직 quota 부족 메시지와 함께 요청 실패
- 조직 구독 한도 부족: 조직 구독 한도 부족 메시지와 함께 요청 실패
- 일반 조직 사용자 관리 접근: 권한 없음
- 조직 밖 사용자 수정: 권한 없음
- 비활성 또는 다른 조직의 플랜 할당: 실패
- 이미 active 플랜이 있는 사용자에게 새 플랜을 할당할 경우: 기존 active 플랜을 취소하고 새 플랜 생성

프론트엔드는 API 실패 시 toast 또는 화면 안내로 원인을 표시한다.

## 14. 데이터베이스 호환성

마이그레이션과 쿼리는 SQLite, MySQL 5.7.8 이상, PostgreSQL 9.6 이상을 모두 지원해야 한다.

설계 원칙:

- 가능한 GORM API를 사용한다.
- raw SQL이 필요한 경우 DB별 quoting과 boolean 표현 차이를 고려한다.
- JSON 저장이 필요하면 DB 전용 JSON 타입 대신 `TEXT`를 우선한다.
- SQLite에서 지원하지 않는 `ALTER COLUMN` 방식은 사용하지 않는다.

## 15. 테스트 요구사항

백엔드 테스트:

- 조직 생성과 조직 소유자 지정
- 조직과 무관한 사용자만 조직 소유자로 선택 가능
- 조직 admin/owner 권한 검증
- 조직 밖 사용자 관리 차단
- 조직 quota 선차감, 정산, 환불
- 조직 quota 부족 시 요청 실패
- 조직 구독 한도 선차감, 정산, 환불
- 조직 구독 한도 부족 시 요청 실패
- 조직 구독 사용자는 사용자 quota로 fallback하지 않음
- active 구독 자동 갱신
- 구독 취소 시 만료 시간과 무관하게 active 구독 취소
- 동일 사용자에게 여러 active 조직 구독이 남지 않음
- 조직 대시보드가 조직 내부 로그만 집계

프론트엔드 검증:

- 조직 일반 사용자는 조직 관리 메뉴를 볼 수 없음
- 조직 소유자/관리자는 조직 관리 메뉴를 볼 수 있음
- 전체 관리자는 조직 선택 후 조직 대시보드/로그/구독을 조회할 수 있음
- 조직 선택 값이 메뉴 이동 후에도 유지됨
- 조직 구독 사용자는 지갑에서 잔액 대신 `조직 플랜 사용 중`을 봄
- 조직 구독 사용자는 조직 사용자 화면에서 quota 입력이 비활성화됨
- active 플랜 사용자는 플랜 할당 드롭다운에서 제외됨
- 플랜 취소 후 목록에서 사라지고 다시 할당 가능해짐
- 한국어 UI에서 지갑 화면의 주요 문구가 번역됨

## 16. 운영 및 수동 테스트 시나리오

### 16.1 조직 생성

1. 전체 관리자로 로그인한다.
2. 조직 사용자 메뉴에서 조직을 생성한다.
3. 소유자는 조직과 무관한 일반 사용자 중에서 선택한다.
4. 조직 quota를 초기값으로 입력한다.
5. 조직 생성 후 조직 목록에 표시되는지 확인한다.

### 16.2 조직 quota 방식 테스트

1. 조직 소유자로 로그인한다.
2. 조직 사용자를 추가한다.
3. 사용자 quota와 조직 quota를 충분히 설정한다.
4. 조직 일반 사용자로 API 요청을 수행한다.
5. 사용자 사용량과 조직 사용량이 함께 증가하는지 확인한다.

### 16.3 조직 구독 방식 테스트

1. 조직 소유자 또는 조직 관리자로 로그인한다.
2. 조직 구독 메뉴에서 플랜을 만든다.
3. 조직 사용자에게 플랜을 할당한다.
4. 해당 사용자로 지갑 화면에 들어가 `조직 플랜 사용 중`이 보이는지 확인한다.
5. API 요청 후 조직 구독 사용량과 조직 quota 사용량이 증가하는지 확인한다.
6. 플랜 한도를 초과하면 요청이 실패하는지 확인한다.
7. 플랜 취소 후 해당 사용자가 다시 일반 quota 방식으로 돌아가는지 확인한다.

### 16.4 조직 모니터링 테스트

1. 조직 소유자 또는 조직 관리자로 로그인한다.
2. 조직 대시보드에서 기간별 사용량, 사용자별 차트, 모델별 차트를 확인한다.
3. 조직 사용 로그와 작업 로그에서 조직 내부 사용자 기록만 보이는지 확인한다.
4. 전체 관리자로 로그인한 뒤 조직을 선택하고 같은 화면을 조회한다.
5. 다른 메뉴로 이동 후 돌아와도 마지막 조직 선택이 유지되는지 확인한다.

## 17. 향후 확장 후보

향후 확장 가능한 항목은 다음과 같다.

- 조직 초대 링크

- 조직 단위 API key

- 조직 권한을 더 세분화한 RBAC
