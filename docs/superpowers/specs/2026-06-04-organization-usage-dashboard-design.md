# 조직 사용량 대시보드 설계

## 배경

조직 쿼터 구조가 추가되면서 조직 소유자와 조직 관리자는 조직 전체의 잔여 쿼터, 누적 사용량, 기간별 사용량을 운영 관점에서 확인할 필요가 생겼다. 현재 지갑 화면은 잔여 쿼터와 누적 사용량 확인에 가깝고, 조직 내 사용자가 어떤 방식으로 쿼터를 소비하는지 한눈에 보기 어렵다.

이 기능은 조직 소유자와 조직 관리자에게 조직 범위의 사용량 대시보드를 제공한다. 일반 조직 사용자는 접근할 수 없다.

## 목표

- 조직 소유자와 조직 관리자가 조직 전체 사용량을 모니터링할 수 있게 한다.
- 기본 기간은 최근 7일로 하고, 오늘, 최근 30일, 사용자 지정 기간을 선택할 수 있게 한다.
- 조직 잔여 쿼터, 조직 누적 사용량, 기간 내 사용량, 기간 내 요청 수를 요약 카드로 보여준다.
- 기간별 사용량 추이, 상위 사용자, 상위 모델을 보여준다.
- 기존 관리자 대시보드와 로그 집계 흐름을 가능한 재사용하되, API와 권한 경계는 조직 전용으로 분리한다.

## 비목표

- 전체 관리자용 전역 대시보드를 대체하지 않는다.
- 조직 관리자가 조직 밖 사용자의 로그나 사용량을 볼 수 있게 하지 않는다.
- 조직 사용량의 과금 정산 방식을 추가로 변경하지 않는다.
- 실시간 스트리밍 대시보드나 알림 기능은 이번 범위에 포함하지 않는다.

## 접근 방식

백엔드에는 조직 전용 엔드포인트를 추가한다. 엔드포인트는 현재 로그인 사용자의 `organization_id`와 `organization_role`을 기준으로 접근을 제한한다. 내부 집계는 기존 usage log, quota data, dashboard 계열 로직을 최대한 재사용하되, 모든 쿼리에는 조직 사용자 범위 조건을 적용한다.

프론트엔드에는 `/organization/dashboard` 화면을 추가한다. 조직 소유자와 조직 관리자는 이 화면에서 조직 사용량을 확인하고, 필요하면 조직 사용자 관리나 로그 화면으로 이동할 수 있다.

## 권한

- 접근 가능: 조직 소유자, 조직 관리자
- 접근 불가: 일반 조직 사용자, 조직이 없는 사용자
- 전체 관리자가 이 API를 호출하더라도 기본 동작은 "현재 사용자가 속한 조직" 기준이다.
- 전체 관리자의 전역 조회 기능은 별도 관리자 대시보드에서 유지한다.

권한 검증은 백엔드에서 반드시 수행한다. 프론트엔드의 메뉴 노출 여부는 편의 기능일 뿐 보안 경계로 사용하지 않는다.

## 백엔드 API

### `GET /api/organization/dashboard`

요청 쿼리:

- `start_timestamp`: 선택, Unix timestamp
- `end_timestamp`: 선택, Unix timestamp
- `preset`: 선택, `today`, `7d`, `30d`, `custom`

기본값:

- 기간 파라미터가 없으면 최근 7일을 사용한다.

응답 예시:

```json
{
  "organization": {
    "id": 1,
    "name": "atto",
    "quota": 499975,
    "used_quota": 25
  },
  "summary": {
    "period_quota": 25,
    "period_requests": 1,
    "member_count": 3,
    "active_member_count": 1
  },
  "daily_usage": [
    {
      "date": "2026-06-04",
      "quota": 25,
      "requests": 1
    }
  ],
  "top_users": [
    {
      "user_id": 10,
      "username": "atto.1",
      "display_name": "atto.1",
      "quota": 1000,
      "used_quota": 25,
      "period_quota": 25,
      "period_requests": 1
    }
  ],
  "top_models": [
    {
      "model": "gpt-4o-mini",
      "quota": 25,
      "requests": 1
    }
  ]
}
```

## 데이터 집계

- 조직 기본 정보는 `organizations` 테이블에서 읽는다.
- 조직 사용자 목록은 `users.organization_id`로 필터링한다.
- 기간 내 사용량은 사용 로그 테이블에서 `user_id IN (조직 사용자 ID 목록)` 조건으로 집계한다.
- 사용자별 표는 `users`의 `quota`, `used_quota`, `request_count`와 기간 내 로그 집계를 함께 사용한다.
- 모델별 집계는 기간 내 로그의 모델명과 quota를 기준으로 계산한다.

조직에 사용자가 없는 경우에는 빈 차트와 빈 표를 반환하고, 요약 값은 0으로 반환한다.

## 프론트엔드 화면

경로:

- `/organization/dashboard`

구성:

- 상단 기간 선택: 오늘, 최근 7일, 최근 30일, 사용자 지정
- 요약 카드: 조직 잔여 쿼터, 조직 누적 사용량, 기간 내 사용량, 기간 내 요청 수
- 차트: 날짜별 사용량 추이
- 표: 상위 사용자
- 표 또는 차트: 상위 모델

일반 조직 사용자가 접근하면 권한 없음 안내를 표시하거나 기존 조직 지갑 요약으로 안내한다. 조직이 없는 사용자는 조직 기능을 사용할 수 없다는 안내를 표시한다.

## 오류 처리

- 조직이 없는 사용자: 403 또는 명확한 클라이언트 안내
- 조직 일반 사용자: 403
- 비활성 조직: 403
- 잘못된 기간 파라미터: 400
- 집계 중 데이터가 없는 경우: 200과 빈 배열

프론트엔드는 403, 400, 네트워크 오류를 각각 구분해서 표시한다.

## 테스트 계획

백엔드:

- 조직 소유자는 대시보드 API에 접근할 수 있다.
- 조직 관리자는 대시보드 API에 접근할 수 있다.
- 조직 일반 사용자는 접근할 수 없다.
- 조직이 없는 사용자는 접근할 수 없다.
- 응답 집계는 조직 내 사용자 로그만 포함한다.
- 조직 밖 사용자의 로그는 포함하지 않는다.
- 기간 필터가 적용된다.

프론트엔드:

- 조직 소유자/관리자에게 메뉴와 대시보드가 보인다.
- 조직 일반 사용자에게는 접근 불가 안내가 보인다.
- 기간 선택을 바꾸면 데이터가 다시 조회된다.
- 빈 데이터 상태가 깨지지 않는다.

## 구현 순서

1. 백엔드 조직 대시보드 DTO와 서비스 함수를 추가한다.
2. 백엔드 API 라우트와 권한 검증을 추가한다.
3. 백엔드 테스트를 먼저 작성하고 실패를 확인한다.
4. 집계 로직을 구현하고 테스트를 통과시킨다.
5. 프론트엔드 API 클라이언트와 타입을 추가한다.
6. `/organization/dashboard` 화면을 추가한다.
7. 조직 관리자/소유자 메뉴 진입점을 추가한다.
8. 프론트엔드 빌드와 백엔드 테스트를 실행한다.
