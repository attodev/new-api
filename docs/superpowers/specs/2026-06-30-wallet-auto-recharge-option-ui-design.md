# 정기 충전/자동 충전 옵션형 UI 설계

## 배경

현재 정기 충전과 자동 충전은 관리자 프리셋 하나가 사용자가 선택할 완성 정책 하나를 의미한다. 정기 충전 프리셋은 기간과 충전 금액을 함께 갖고, 자동 충전 프리셋은 충전 금액과 기준 금액을 함께 갖는다.

이 구조는 구현은 단순하지만 사용자 화면에서는 비슷한 카드가 여러 개 나열되어 선택 부담이 커진다. 관리자가 원하는 정책도 "월별 10,000원/30,000원/50,000원"처럼 기간과 금액 선택지의 조합에 가까우므로, 화면은 선택지 관리와 단계형 선택 흐름으로 바꾸는 것이 더 자연스럽다.

## 목표

- 기존 DB/API/정책 생성 흐름은 유지한다.
- 관리자 화면은 개별 프리셋 행 편집 대신 옵션 묶음 관리처럼 보이게 한다.
- 사용자 화면은 정기 충전과 자동 충전을 버튼 기반 단계형 선택으로 단순화한다.
- 기존 프리셋 데이터는 화면 진입 시 그룹화해서 계속 사용할 수 있게 한다.
- 저장 시 현재 화면에 없는 기존 프리셋은 삭제하지 않고 비활성화한다.

## 비목표

- 새로운 DB 테이블을 만들지 않는다.
- 기존 정책 생성 API의 결제 플로우를 바꾸지 않는다.
- Toss 외 결제 수단을 추가하지 않는다.
- 기존 활성 정책을 자동으로 변경하지 않는다.

## 데이터 해석

기존 `WalletAutoRechargePreset` 행을 그대로 저장 단위로 사용한다.

정기 충전:

- 하나의 프리셋 행은 `기간 옵션 + 충전 금액` 조합이다.
- `interval_unit=day, interval_value=1`은 일별로 표시한다.
- `interval_unit=day, interval_value=7`은 주별로 표시한다.
- `interval_unit=month, interval_value=1`은 월별로 표시한다.
- 그 외 `day/month/custom` 조합은 커스텀 기간으로 표시한다.
- 같은 기간과 같은 금액의 중복 프리셋이 있으면 `sort_order`, `id` 순으로 앞선 행을 대표로 사용한다.

자동 충전:

- 하나의 프리셋 행은 `충전 금액 + 기준 금액` 조합이다.
- 같은 충전 금액과 같은 기준 금액의 중복 프리셋이 있으면 `sort_order`, `id` 순으로 앞선 행을 대표로 사용한다.

## 관리자 화면

관리자 메뉴는 기존 정기 충전/자동 충전 프리셋 관리 위치를 유지하되, 화면 구성을 옵션형으로 바꾼다.

정기 충전 영역:

- 기간 옵션 목록을 관리한다.
- 각 기간 옵션 안에서 충전 금액 목록을 관리한다.
- 일별, 주별, 월별은 빠른 선택으로 제공한다.
- 커스텀 기간은 `interval_unit`, `interval_value`, `custom_seconds` 입력을 제공한다.
- 저장 시 각 `기간 x 충전 금액` 조합을 기존 프리셋 행으로 생성하거나 활성화한다.
- 화면에서 제거된 조합은 기존 행을 비활성화한다.

자동 충전 영역:

- 충전 금액 목록을 관리한다.
- 기준 금액 목록을 관리한다.
- 저장 시 각 `충전 금액 x 기준 금액` 조합을 기존 프리셋 행으로 생성하거나 활성화한다.
- 화면에서 제거된 조합은 기존 행을 비활성화한다.

공통:

- 대상 범위는 기존처럼 `전체`, `사용자`, `조직`을 지원한다.
- 처음에는 단순화를 위해 각 옵션 묶음의 대상 범위를 하나로 관리한다.
- 기존 데이터에 대상 범위가 섞여 있으면 화면에는 모두 표시하되, 저장 시 현재 선택한 대상 범위로 정규화한다.
- 비활성 프리셋은 관리자 화면에서 기존 데이터 복원을 위해 읽어오지만 사용자 화면에는 노출하지 않는다.

## 사용자 화면

정기 충전:

- 활성 프리셋을 기간별로 묶는다.
- 기간 후보가 하나뿐이면 기간 선택 UI를 숨기고 충전 금액 버튼만 표시한다.
- 기간 후보가 여러 개이면 기간 버튼을 먼저 표시한다.
- 기간 선택 후 해당 기간의 충전 금액 버튼을 표시한다.
- 충전 금액 버튼을 누르면 대표 프리셋 ID로 기존 Toss 빌링키 등록 흐름을 시작한다.

자동 충전:

- 활성 프리셋을 충전 금액별로 묶는다.
- 충전 금액 버튼을 먼저 표시한다.
- 충전 금액 선택 후 기준 금액 버튼을 표시한다.
- 기준 금액 후보가 하나뿐이면 두 번째 선택 없이 대표 프리셋 ID로 진행한다.
- 여러 기준 금액이 있으면 기준 금액 버튼을 눌렀을 때 기존 Toss 빌링키 등록 흐름을 시작한다.

## 오류 처리

- 조합 저장 중 일부 API 요청이 실패하면 오류 토스트를 표시하고 목록을 다시 불러온다.
- 충전 금액이 Toss 최소 충전 금액보다 작으면 기존 서버 검증 오류를 그대로 표시한다.
- 사용자가 선택한 조합이 저장 직후 비활성화되었거나 삭제된 경우 기존 API 오류를 표시한다.
- 활성 정책이 이미 있으면 기존처럼 취소 버튼만 제공하고 새 정책 선택은 막는다.

## 테스트

프론트 테스트:

- 정기 충전 프리셋을 기간별로 묶고 기간이 하나면 기간 선택을 숨기는지 검증한다.
- 정기 충전에서 기간 선택 후 올바른 금액 버튼이 표시되고 대표 프리셋 ID로 생성 요청하는지 검증한다.
- 자동 충전에서 충전 금액 선택 후 기준 금액 버튼이 표시되는지 검증한다.
- 자동 충전에서 기준 금액 후보가 하나면 충전 금액 선택만으로 대표 프리셋 ID를 사용하는지 검증한다.
- 관리자 옵션 화면이 기존 프리셋 목록을 옵션 묶음으로 변환하는지 검증한다.
- 관리자 저장 로직이 필요한 조합 생성/활성화와 사라진 조합 비활성화를 계산하는지 검증한다.

백엔드 테스트:

- 기존 프리셋 검증과 정책 생성 테스트를 유지한다.
- 이번 변경은 DB/API 변경을 피하므로 백엔드 신규 동작 테스트는 최소화한다.

## 배포 영향

- 기존 프리셋 행과 활성 정책은 유지된다.
- 사용자 화면의 선택 방식만 바뀐다.
- 관리자 화면에서 저장하면 기존 프리셋 행 일부가 비활성화될 수 있으나 삭제되지는 않는다.
