# 조직 선불 quota 지갑 설계

## 목표

조직 사용자가 API를 사용할 때 최종 비용을 조직 자체의 선불 quota 지갑에서 정산한다. 전체 관리자는 조직 사용자도 일반 사용자처럼 보되, 조직 단위로 미리 확보한 quota 안에서 조직 전체가 사용하도록 한다.

## 결정 사항

- 조직 구성원이 요청하면 실제 호출자는 그대로 해당 사용자로 기록한다.
- 조직 구성원의 개인 quota는 조직 내부 사용 한도처럼 차감한다.
- 조직 자체의 quota는 전체 관리자에게 받은 조직 예산 지갑처럼 차감한다.
- 조직 소유자의 개인 quota는 조직 사용량으로 차감하지 않는다.
- 조직 소유자 본인이 조직 소속으로 요청하는 경우에도 조직 quota와 본인 한도만 차감한다.
- 사용량 로그의 `user_id`는 실제 호출자 기준으로 유지한다. 조직 합산 사용량 화면은 별도 기능으로 확장한다.

## 과금 흐름

조직이 없는 사용자는 기존과 동일하게 본인 quota만 차감한다. 조직 사용자는 개인 quota 한도와 조직 quota 잔액을 모두 통과해야 요청할 수 있다.

조직 구성원은 선차감 시점에 개인 한도와 조직 지갑을 모두 확인한다.

```text
조직 사용자 요청 비용 = 25 quota

사용자 quota: 1000 -> 975
조직 quota: 500000 -> 499975
조직 used_quota: 0 -> 25
사용자 used_quota: +25
로그 user_id: 실제 사용자
```

정산 단계에서는 실제 비용과 선차감의 차액을 사용자 quota와 조직 quota에 동일하게 반영한다. 실패하거나 환불이 발생하면 두 quota 모두 환불한다.

## 권한 의미

조직 owner/admin은 조직 내 사용자의 quota 한도를 관리한다. 이 quota는 전체 관리자에게 직접 정산되는 wallet이 아니라 조직 내부 사용 한도다. 전체 관리자에게 정산되는 주체는 조직 레코드의 선불 quota 지갑이다.

## 구현 범위

- 조직 레코드에 `quota`, `used_quota`를 추가한다.
- 조직 quota 조정 헬퍼를 model 계층에 추가한다.
- wallet funding 계층에 조직 구성원용 funding source를 추가한다.
- BillingSession 생성 시 조직 구성원은 개인 한도와 조직 quota 잔액을 함께 검사한다.
- 기존 사용량 기록은 실제 호출자 기준으로 유지한다.
- 조직 owner/admin이 조직 quota 잔액과 사용량을 볼 수 있는 profile API/UI를 추가한다.
- root가 조직 생성 시 초기 quota를 지정하고, 이후 조직 quota를 조정할 수 있는 API/UI를 추가한다.

## 테스트

- 조직 구성원이 선차감되면 구성원 quota와 조직 quota가 함께 줄어드는지 확인한다.
- 조직 구성원의 실제 비용이 선차감보다 적으면 두 quota가 함께 환불되는지 확인한다.
- 조직 소유자 개인 quota는 조직 사용량으로 줄지 않는지 확인한다.
- 조직 quota 잔액이 부족하면 조직 구성원 요청이 거절되는지 확인한다.
