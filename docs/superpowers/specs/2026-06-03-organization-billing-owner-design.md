# 조직 과금 책임자 설계

## 목표

조직 사용자가 API를 사용할 때 최종 비용을 조직 소유자에게 귀속한다. 전체 관리자는 조직 사용자를 일반 사용자처럼 보되, 조직 내부에서 발생한 비용은 조직 소유자의 quota 잔액에서 정산되도록 한다.

## 결정 사항

- 조직 구성원이 요청하면 실제 호출자는 그대로 해당 사용자로 기록한다.
- 조직 구성원의 개인 quota는 조직 내부 사용 한도처럼 차감한다.
- 조직 소유자의 quota는 전체 관리자에게 받은 조직 예산 지갑처럼 차감한다.
- 조직 소유자 본인이 요청하는 경우에는 같은 계정을 두 번 차감하지 않고 기존 개인 지갑 과금과 동일하게 한 번만 차감한다.
- 사용량 로그의 `user_id`는 실제 호출자 기준으로 유지한다. 조직 합산 사용량 화면은 별도 기능으로 확장한다.

## 과금 흐름

조직이 없는 사용자는 기존과 동일하게 본인 quota만 차감한다.

조직 구성원은 선차감 시점에 두 잔액을 모두 확인한다.

```text
조직 사용자 요청 비용 = 25 quota

사용자 quota: 1000 -> 975
조직 소유자 quota: 500000 -> 499975
사용자 used_quota: +25
로그 user_id: 실제 사용자
```

정산 단계에서는 실제 비용과 선차감의 차액을 사용자 quota와 조직 소유자 quota에 동일하게 반영한다. 실패하거나 환불이 발생하면 두 quota 모두 환불한다.

## 권한 의미

조직 owner/admin은 조직 내 사용자의 quota 한도를 관리한다. 이 quota는 전체 관리자에게 직접 정산되는 wallet이 아니라 조직 내부 사용 한도다. 전체 관리자에게 정산되는 주체는 조직 소유자 계정이다.

## 구현 범위

- 조직 owner 조회 헬퍼를 model 계층에 추가한다.
- wallet funding 계층에 조직 구성원용 funding source를 추가한다.
- BillingSession 생성 시 조직 구성원은 개인 한도와 owner 잔액을 함께 검사한다.
- 기존 사용량 기록은 실제 호출자 기준으로 유지한다.
- 조직 사용량 조회 화면/API는 다음 단계로 분리한다.

## 테스트

- 조직 구성원이 선차감되면 구성원 quota와 owner quota가 함께 줄어드는지 확인한다.
- 조직 구성원의 실제 비용이 선차감보다 적으면 두 quota가 함께 환불되는지 확인한다.
- owner 본인이 요청하면 한 번만 차감되는지 확인한다.
- owner 잔액이 부족하면 조직 구성원 요청이 거절되는지 확인한다.
