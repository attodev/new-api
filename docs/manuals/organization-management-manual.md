# 조직 관리 기능 사용자 매뉴얼

## 1. 개요

이 매뉴얼은 조직 생성, 조직 사용자 관리, 조직 quota 지갑, 조직 사용량 모니터링, 조직 전용 구독 플랜을 UI에서 사용하는 방법을 설명한다.

조직 기능은 기존 사용자 `group`과 별개로 동작한다. `group`은 모델 접근과 과금 그룹 용도로 유지되며, 조직 소속은 별도 조직 필드로 관리된다.

표기 기준 (2026-10-14, upstream 재기반 develop):

- 웹 콘솔에는 아직 한국어 locale이 없어(단계 D) 메뉴·버튼이 영문으로 보인다. 이 문서는 화면에 보이는 영문 라벨을 `Organization Users`처럼 그대로 적고, 필요하면 우리말 설명을 붙인다.
- 조직 메뉴 주소: `Organization Users` `/organization`, `Organization Dashboard` `/organization/dashboard`, `Organization Usage Logs` `/organization/usage-logs/common`, `Organization Task Logs` `/organization/usage-logs/task`(그리기 로그는 `/organization/usage-logs/drawing`), `Organization Subscription` `/organization/subscriptions`. 지갑은 `/wallet` 하나이고, 로그인한 사용자의 조직 역할에 따라 화면이 바뀐다.
- API 경로는 `docs/openapi/organization-rest-api.md`를 따른다.
- 결제 provider는 Epay, Stripe, PayPal, Creem, Waffo, Waffo Pancake 6종이다. Toss 결제와 지갑 자동충전·정기결제는 develop에 없다.

## 2. 역할별 가능 작업

### 전체 관리자

전체 관리자는 모든 조직을 운영 관점에서 관리할 수 있다.

- 조직 생성
- 조직 소유자 지정 (생성 시에만. 소유권 이전 기능은 없다)
- 조직 quota 조정 (조직 지갑을 관리자가 직접 채우는 경로)
- 조직 삭제 (owner 외 구성원을 모두 제거한 뒤)
- 조직 대시보드 조회
- 조직 사용 로그 조회
- 조직 작업 로그 조회
- 조직 구독 플랜 조회 및 관리 (조직의 owner에게 플랜을 할당·취소하는 것도 가능)
- 조직 사용자 목록 Export/Import
- 조직 선택 후 조직 사용자 목록 확인 (읽기 전용 — 멤버 추가·역할·quota·상태·제거는 조직 소유자/관리자가 한다)

### 조직 소유자

조직 소유자는 자기 조직의 운영 책임자다.

- 조직 사용자 추가 (추가할 때 `member`/`admin` 역할 선택 가능)
- 조직 사용자 역할 관리 (member ↔ admin. 화면의 Role 드롭다운은 소유자에게만 보인다)
- 조직 사용자 quota 조정
- 조직 지갑 조회와 충전 (소유자 전용)
- 조직 대시보드 조회
- 조직 사용 로그 조회
- 조직 작업 로그 조회
- 조직 구독 플랜 생성, 수정, 비활성화
- 조직 사용자에게 구독 플랜 할당, 변경, 취소

### 조직 관리자

조직 관리자는 자기 조직의 사용자 사용량과 구독을 관리한다.

- 조직 사용자 목록 조회
- 조직 사용자 추가 (username/email 정확 조회 후 추가. 화면에서는 `member`로 추가. API로는 `admin`으로도 추가 가능)
- 조직 사용자 역할 변경 (member ↔ admin. 화면에는 Role 드롭다운이 없어 API `PUT /api/organization/users/:id/membership`로 한다)
- 조직 사용자 상태 관리
- 조직 사용자 quota 조정
- 조직 사용자 제거
- 조직 사용자 목록 Export/Import
- 조직 대시보드 조회
- 조직 사용 로그 조회
- 조직 작업 로그 조회
- 조직 구독 플랜 생성, 수정, 비활성화
- 조직 사용자에게 구독 플랜 할당, 변경, 취소 (owner 제외)

조직 관리자와 소유자 공통 제약:

- 자기 자신의 역할·quota·상태는 바꾸거나 제거할 수 없다. 자기 행은 화면에서 잠겨 있다(`You cannot modify your own membership`).
- owner 행은 owner 본인만 바꿀 수 있다. 관리자에게 owner 행은 잠겨 있다(`Owner cannot be modified`).
- 누구도 `owner` 역할을 부여할 수 없다. 소유권은 조직 생성 때 정해진다.
- 조직 지갑 충전은 소유자 전용이다. 관리자에게도 `Top up organization wallet` 버튼이 보이지만 `/wallet`에서는 구성원 요약 화면이 열린다.

### 조직 일반 사용자

조직 일반 사용자는 관리 기능을 사용할 수 없다.

- 자기 지갑 화면에서 조직이 할당한 quota 또는 조직 플랜 상태 확인
- API 요청 사용
- 자기 사용량과 요청 수 확인

## 3. 기본 개념

### 조직 quota

조직 quota는 조직 전체가 사용하는 선불 지갑이다. 조직 사용자가 API를 사용하면 최종 비용은 조직 quota에서 차감된다.

조직 quota가 부족하면 조직 구성원의 개인 quota 또는 구독 한도가 남아 있어도 요청은 실패한다.

### 사용자 quota

사용자 quota는 조직 내부에서 사용자별 사용 한도로 쓰인다.

조직 구독 플랜이 없는 사용자는 사용자 quota와 조직 quota가 모두 충분해야 요청할 수 있다.

### 조직 구독 플랜

조직 구독 플랜은 조직 내부 사용자에게 할당하는 별도 사용 한도다. 사용자가 직접 구매하거나 변경할 수 없다.

조직 구독 플랜을 받은 사용자는 개인 quota 대신 구독 플랜 한도를 사용한다. 이때도 최종 비용은 조직 quota에서 함께 차감된다.

### 조직 구독 자동 갱신

조직 구독은 플랜 기간이 끝나면 자동 갱신된다. `active` 상태의 구독은 만료 시간이 지나도 다음 사용 시 갱신 대상이 될 수 있다.

구독을 삭제하거나 취소하면 해당 사용자의 active 구독이 모두 취소되고 더 이상 자동 갱신되지 않는다.

### 조직을 떠날 때의 quota

멤버십을 제거하거나 조직을 삭제하면 떠나는 사용자의 `users.quota`(조직이 배정한 사용자 quota)는 0이 된다. 조직 구성원은 개인 충전을 하지 않으므로 이 값은 조직이 준 한도이고, 개인 잔액으로 남기지 않는다. 이전 값은 감사 로그(`organization.user.remove`, `organization.delete`)의 `previous_quota`에 남는다.

## 4. 전체 관리자로 조직 생성하기

1. 전체 관리자 계정으로 로그인한다.
2. 사이드바 `Organization` 그룹의 `Organization Users`(`/organization`)로 이동한다.
3. `Create Organization` 영역의 `Organization Name`에 조직 이름을 입력한다.
4. 필요한 경우 `Description`에 설명을 입력한다.
5. `Initial organization quota`에 초기 조직 quota를 입력한다.
6. `Owner User`에서 소유자 사용자를 선택한다.
7. `Create` 버튼을 누른다.

주의할 점:

- 조직 소유자 선택 목록에는 조직에 속하지 않은 일반 사용자만 표시된다.
- 이미 다른 조직에 속한 사용자는 새 조직 소유자로 선택할 수 없다.
- 전역 관리자 또는 수퍼 관리자는 조직 소유자 후보에서 제외된다(화면 목록 기준. API는 이 검사를 하지 않는다).
- 소유자 후보 목록은 사용자 목록 첫 50명 중 조직 미소속 일반 사용자다.
- 조직 이름은 64자 이하로 입력해야 한다.
- 설명은 255자 이하로 입력해야 한다.
- 초기 조직 quota는 0 이상 9,007,199,254,740,991(2^53-1) 이하만 저장할 수 있다.

## 5. 전체 관리자로 조직 quota 조정하기

1. 전체 관리자 계정으로 로그인한다.
2. `Organization Users` 메뉴로 이동한다.
3. `Manage organization quota` 영역에서 대상 조직을 찾아 `Edit`를 누른다.
4. 위쪽 `Edit Organization` 폼의 quota 입력칸에 새 금액을 입력한다.
5. `Save` 버튼을 누른다.

API로는 `PATCH /api/organizations/:id`에 `{"quota": <quota 단위 값>}`을 보낸다.

입력값은 화면의 currency/quota 표시 설정에 따라 금액 또는 token 기준으로 변환된다. 일반적인 금액 표시 모드에서는 `1`을 입력하면 `$1`에 해당하는 quota로 저장된다.

조직 quota는 서버에서 0 이상 9,007,199,254,740,991(2^53-1) 이하로 제한한다. 화면에서 금액 단위로 보이더라도 저장 전 quota 단위로 변환된 값이 이 범위를 넘어가면 저장되지 않는다.

## 5-1. 전체 관리자로 조직 삭제하기

1. 조직 소유자 또는 관리자가 owner 외 구성원을 모두 제거한다(6-2).
2. 전체 관리자로 `Organization Users`의 `Manage organization quota` 영역에서 대상 조직의 `Delete`를 누른다.
3. `Delete Organization` 확인 창에서 `Delete`를 누른다.

구성원이 남아 있으면 `organization has N non-owner members, remove them first` 오류로 거부된다. 삭제되면 owner는 조직에서 빠지고 owner의 사용자 quota는 0이 된다.

## 6. 조직 관리자/소유자로 사용자 추가하기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다.
2. `Organization Users` 메뉴로 이동한다.
3. `Assign Organization Member` 영역의 `Username or email` 칸에 추가할 사용자의 username 또는 email을 **정확히** 입력한다.
4. `Look up user` 버튼을 누른다 (또는 Enter 키).
5. 사용자를 찾으면 결과 한 줄(username, 표시 이름)이 나온다. 없으면 `User not found`가 표시된다.
6. 소유자는 결과 줄의 역할 선택(`member`/`admin`)을 고른다. 관리자 화면에는 역할 선택이 없고 `member`로 추가된다.
7. `Add` 버튼을 누른다. 성공하면 `Organization member assigned`가 표시되고 사용자 목록이 갱신된다.

동작 정책:

- 미소속 사용자 목록은 보여주지 않는다. 입력값에 `@`가 있으면 email로, 없으면 username으로 조회하며 부분 일치는 하지 않는다(email은 대소문자 무시). 조회 결과에는 잔액·비고가 나오지 않는다.
- 조직 미소속 일반 사용자와 같은 조직 구성원만 찾을 수 있다. 다른 조직 소속 사용자와 전역 관리자는 `User not found`로 나온다.
- **개인 잔액이 남은 사용자는 추가할 수 없다.** 개인 잔액(quota)이 0보다 크거나 활성 개인 구독이 있으면 `Add`가 `This user still has a personal balance or subscription`으로 거부된다. 조직에 들어오면 개인 quota가 조직 관리자가 정하는 한도로 바뀌기 때문이다. 사용자가 잔액을 다 쓰거나 구독이 끝난 뒤, 또는 전체 관리자가 사용자 관리에서 잔액을 0으로 정리하고 구독을 취소한 뒤 다시 추가한다. 초대·수락 절차는 없다.
- Excel 가져오기도 같다. 잔액이나 활성 구독이 있는 기존 사용자 행은 `failed to assign: user still has a personal balance or subscription` 행 오류가 된다. 가져오기가 새로 만드는 사용자는 해당하지 않는다.
- 역할 변경은 사용자 테이블의 Role 컬럼(소유자 화면)이나 API로 따로 수행한다.

## 6-1. 조직 사용자 역할 변경하기

1. 조직 소유자 계정으로 로그인한다.
2. `Organization Users` 메뉴로 이동한다.
3. 테이블에서 역할을 변경할 사용자 행의 `Role` 컬럼을 찾는다.
4. 드롭다운에서 `member` 또는 `admin`을 선택한다.
5. 변경 배너(`{{count}} role changes`)가 나타나면 `Save` 버튼을 누른다.

제약:

- owner 행과 자기 자신의 행은 역할 변경 불가.
- 드롭다운에는 `member`, `admin`만 있다. `owner` 역할은 누구도 부여할 수 없다.
- Role 드롭다운은 소유자 화면에만 보인다. 조직 관리자는 같은 변경(`member` ↔ `admin`)을 API `PUT /api/organization/users/:id/membership`로 할 수 있다.

## 6-2. 조직 사용자 제거하기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다.
2. `Organization Users` 메뉴로 이동한다.
3. 제거할 사용자의 체크박스를 선택한다 (다중 선택 가능).
4. 검색창 옆 툴바에서 `Remove from organization` 버튼을 누른다.
5. 해당 사용자가 `Pending removal` 상태(취소선 표시)로 표시된다.
6. 변경 배너에서 `Save`를 눌러 확정한다.

제약:

- owner와 자기 자신은 제거 불가 (체크박스 disabled).
- 제거 후 해당 사용자는 조직에서 탈퇴되며 일반 사용자로 전환된다. 이때 사용자 quota는 0이 된다(3장 "조직을 떠날 때의 quota").

## 7. 조직 사용자 quota 관리하기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다.
2. `Organization Users` 메뉴로 이동한다.
3. 사용자 목록에서 quota 영역을 확인한다.
4. quota 입력칸에 새 값을 입력한다.
5. Enter를 누르거나 입력칸 밖으로 이동해 저장한다.

빠른 버튼:

- `$1`
- `$5`
- `$10`
- `$100`

조직 구독 플랜이 할당된 사용자는 quota 입력칸이 비활성화된다. 이 경우 현재 quota 자리에 `Organization plan in use`가 표시된다.

자기 자신과 owner 행(관리자 화면)은 quota 입력칸이 잠겨 있다.

서버 검증 기준:

- 사용자 quota: 0 이상 9,007,199,254,740,991(2^53-1) 이하
- 사용자 상태: 활성 또는 비활성 값만 허용
- remark: 255자 이하 (remark는 화면에서 편집하지 않는다. API `PATCH /api/organization/users/:id` 또는 Excel 가져오기로 바꾼다)

## 8. 조직 지갑 사용하기

### 조직 소유자

조직 소유자가 지갑 메뉴(`/wallet`)에 들어가면 개인 지갑 대신 `Organization wallet` 화면이 열린다.

확인 가능한 정보:

- 조직 quota (`Current Balance`)
- 조직 사용량 (`Total Usage`)
- 충전 입력 (`Add Funds`)
- 결제 provider별 결제 버튼 (Epay, Stripe, PayPal, Creem, Waffo, Waffo Pancake 중 관리자가 켠 것)
- 조직 충전 내역 (`Order History`)

교환 코드(redemption) 입력은 조직 지갑에 표시되지 않는다. 결제 provider가 하나도 설정되지 않았으면 `Online topup is not enabled...` 안내만 보인다(2026-10-14 수동 실행에서 확인). Waffo는 금액 확인 창 없이 바로 결제 창을 연다.

### 조직 일반 사용자

조직 관리자와 일반 사용자는 지갑에서 직접 충전할 수 없다. `/wallet`에 구성원 요약 화면(`Organization allocated quota`, `Topups are managed by your organization`)이 열린다.

조직 구독 플랜이 없는 경우:

- 현재 할당량
- 사용량
- 요청 수
- 조직에서 quota를 관리한다는 안내

조직 구독 플랜이 있는 경우:

- 현재 잔액 위치에 `Organization plan in use` 표시
- 사용량은 그대로 표시
- 요청 수는 그대로 표시
- 할당된 조직 플랜 이름, 사용량, 만료일 표시

## 9. 조직 구독 플랜 만들기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다. (전체 관리자는 화면 위에서 조직을 먼저 선택한다.)
2. `Organization Subscription`(`/organization/subscriptions`) 메뉴로 이동한다.
3. `Plan configuration`에서 플랜 제목(`Plan title`)을 입력한다.
4. 필요한 경우 부제목을 입력한다.
5. 금액 또는 quota 값을 입력한다.
6. 기간을 선택한다.
7. 기간이 `사용자 지정`이면 사용자 지정 초를 입력한다.
8. `Create` 버튼을 누른다.

플랜 입력 항목:

- 제목: 플랜 이름
- 부제목: 설명 또는 내부 메모
- 금액: 플랜 기간 동안 사용할 수 있는 한도
- 기간: 플랜 한도가 유지되는 기간
- 사용자 지정 초: 기간이 사용자 지정일 때만 입력 가능

현재 UI에서 제거된 항목:

- quota reset
- reset 사용자 지정 초
- upgrade group

quota reset은 별도로 설정하지 않고 플랜 기간과 동일하게 동작한다.

서버 검증 기준:

- 제목: 1자 이상 128자 이하
- 부제목: 255자 이하
- 금액 또는 quota: 0 이상 9,007,199,254,740,991(2^53-1) 이하
- 기간: 연, 월, 일, 시간, 사용자 지정 중 하나
- 기간 값: 0 이상 1200 이하. 사용자 지정이 아니고 0이면 1로 저장된다.
- 사용자 지정 초: 사용자 지정 기간일 때 1 이상 31,536,000 이하

## 10. 조직 구독 플랜 수정 또는 비활성화하기

1. `Organization Subscription` 메뉴로 이동한다.
2. `Organization plans` 목록에서 수정할 플랜을 찾는다.
3. 수정 버튼을 눌러 폼에 값을 불러온다.
4. 값을 변경한 뒤 저장한다.

플랜을 더 이상 새 사용자에게 할당하지 않으려면 비활성화한다.

주의할 점:

- 비활성화된 플랜은 새 할당 대상에서 제외된다.
- 이미 사용자에게 할당된 구독은 별도 취소 전까지 사용자 구독 목록에 남을 수 있다.

## 11. 사용자에게 조직 구독 플랜 할당하기

1. `Organization Subscription` 메뉴로 이동한다.
2. `Member plan assignment` 영역에서 사용자(`Select user`)를 선택한다.
3. 할당할 플랜(`Select plan`)을 선택한다.
4. `Assign` 버튼을 누른다.

동작 정책:

- 이미 active 플랜이 있는 사용자는 사용자 선택 목록에 표시되지 않는다.
- 같은 사용자에게 여러 active 플랜을 동시에 둘 수 없다.
- 새 플랜을 할당하면 기존 active 플랜은 먼저 취소되고 새 플랜이 생성된다.
- 할당 성공 후 선택한 사용자와 플랜 값은 초기화된다.
- 소유자가 아닌 관리자의 사용자 목록에는 owner가 나오지 않는다. owner에게는 owner 본인이나 전체 관리자가 할당한다.

## 12. 사용자 조직 구독 취소하기

1. `Organization Subscription` 메뉴로 이동한다.
2. 현재 할당된 사용자 목록에서 대상 사용자를 찾는다.
3. `Cancel` 버튼을 누른다. (owner의 플랜은 소유자가 아닌 관리자에게 취소 버튼이 보이지 않는다.)

취소 후 동작:

- 해당 사용자의 active 조직 구독이 모두 취소된다.
- 취소된 구독은 기본 목록에서 숨겨진다.
- 사용자는 다시 일반 quota 방식으로 운영할 수 있다.
- 사용자를 다시 플랜 할당 드롭다운에서 선택할 수 있다.

## 13. 조직 대시보드 확인하기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다.
2. `Organization Dashboard` 메뉴로 이동한다.
3. 기간을 선택한다.

기간 옵션:

- `Today`
- `Last 7 days`
- `Last 30 days`

화면에는 이 세 가지만 있다. 임의 기간은 API(`preset=custom`과 `start_timestamp`/`end_timestamp`)로만 조회한다.

확인 가능한 정보:

- 조직 quota
- 조직 사용량
- 기간 내 사용량
- 기간 내 요청 수
- 날짜별 사용량 추이
- 사용자별 사용량
- 모델별 사용량
- Top 사용자
- Top 모델

전체 관리자는 조직 선택 드롭다운에서 조직을 선택한 뒤 같은 화면을 확인한다.

대시보드 수치는 upstream 사용량 집계(`quota_data`)를 읽으므로 요청 직후가 아니라 집계 주기(`DataExportInterval`, 기본 5분) 뒤에 반영된다. 2026-10-14 수동 실행에서 요청 직후 `period_quota`가 0이었다가 약 5분 뒤 반영되는 것을 확인했다. 조직 잔액·누적 사용량 카드는 바로 바뀐다.

## 14. 조직 사용 로그 확인하기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다.
2. `Organization Usage Logs`(`/organization/usage-logs/common`) 메뉴로 이동한다.
3. 필요한 필터를 적용한다.
4. 로그 상세를 열어 요청 정보를 확인한다.

조직 구독으로 사용한 요청은 로그 상세에 조직 구독 정보가 표시될 수 있다.

예시 정보:

- 조직 구독 ID (`Organization plan` 행)
- 조직 구독 플랜 ID
- 조직 구독 플랜 이름
- 구독 전체 한도
- 선차감 후 사용량

전체 관리자는 화면 오른쪽 위의 조직 선택 드롭다운에서 조직을 선택해 해당 조직의 사용 로그를 본다.

조직 화면에서는 통계 바와 로그 내보내기가 숨겨지고, 사용자 이름을 눌러 여는 사용자 정보 창과 채널 affinity 표시도 꺼진다(사이트 관리자 API가 필요하기 때문). 작업 로그의 작업물(Artifacts) 열은 `-`로 표시된다.

## 15. 조직 작업 로그 확인하기

1. 조직 소유자 또는 조직 관리자 계정으로 로그인한다.
2. `Organization Task Logs`(`/organization/usage-logs/task`) 메뉴로 이동한다. 그리기 작업은 `/organization/usage-logs/drawing`이다.
3. 조직 내부 사용자 작업 기록을 확인한다.

전체 관리자는 조직 선택 후 해당 조직의 작업 로그를 확인할 수 있다.

## 16. 전체 관리자의 조직 선택 유지

전체 관리자가 조직 대시보드, 조직 사용 로그, 조직 작업 로그 화면에서 조직을 선택하면 마지막 선택 조직이 브라우저 localStorage(`organization:last-selected-id`)에 저장된다.

따라서 이 세 화면 사이를 이동했다가 돌아와도 마지막으로 보던 조직이 다시 선택된다. 조직 사용자 화면과 조직 구독 화면은 이 값을 쓰지 않고 목록의 첫 조직에서 시작한다(team과 같은 동작).

## 17. 권장 테스트 순서

### 17.1 기본 조직 quota 방식

1. 전체 관리자로 조직을 생성한다.
2. 조직 소유자를 지정한다.
3. 전체 관리자로 조직 quota를 충분히 설정한다.
4. 조직 소유자로 로그인한다.
5. 조직 일반 사용자를 추가한다.
6. 조직 일반 사용자 quota를 설정한다.
7. 조직 일반 사용자로 API 요청을 실행한다.
8. 지갑에서 사용량과 요청 수가 증가하는지 확인한다.
9. 조직 대시보드에서 조직 사용량이 증가하는지 확인한다.
10. 조직 사용 로그에서 해당 요청이 보이는지 확인한다.

### 17.2 조직 구독 방식

1. 조직 소유자 또는 조직 관리자로 로그인한다.
2. 조직 구독 메뉴에서 플랜을 만든다.
3. 조직 사용자에게 플랜을 할당한다.
4. 해당 사용자로 로그인한다.
5. 지갑에서 `Organization plan in use`가 표시되는지 확인한다.
6. API 요청을 실행한다.
7. 조직 구독의 사용량이 증가하는지 확인한다.
8. 조직 대시보드에서 사용자/모델별 사용량이 표시되는지 확인한다.
9. 플랜 한도를 초과하는 요청이 실패하는지 확인한다.
10. 조직 구독을 취소하고 사용자가 다시 일반 quota 방식으로 돌아가는지 확인한다.

### 17.3 전체 관리자 모니터링

1. 전체 관리자로 로그인한다.
2. 조직 대시보드 메뉴로 이동한다.
3. 조직을 선택한다.
4. 조직 사용 로그와 조직 작업 로그로 이동한다.
5. 선택한 조직이 유지되는지 확인한다(조직 사용자·조직 구독 화면은 첫 조직에서 시작한다).
6. 다른 조직을 선택해 데이터가 바뀌는지 확인한다.

## 18. 자주 발생하는 오류와 대응

### 조직 quota 부족

증상:

- 요청 시 조직 quota 부족 오류가 발생한다.

대응:

- 전체 관리자 또는 조직 소유자가 조직 지갑을 충전한다.
- 전체 관리자는 조직 quota 관리 영역에서 quota를 조정할 수 있다.

### 사용자 quota 부족

증상:

- 조직 구독이 없는 사용자가 요청할 때 사용자 quota 부족 오류가 발생한다.

대응:

- 조직 소유자 또는 조직 관리자가 조직 사용자 화면에서 사용자 quota를 늘린다.

### 조직 구독 한도 부족

증상:

- 조직 구독 플랜 사용자에게 조직 구독 한도 부족 오류가 발생한다.

대응:

- 더 큰 플랜을 할당한다.
- 기존 플랜을 취소하고 일반 quota 방식으로 운영한다.
- 플랜 기간이 지나 자동 갱신되는지 확인한다.

### 오류 문구

조직 과금 오류는 영문으로 나온다. 예: 조직 지갑 부족 `organization quota insufficient, remaining: ＄0.000000` (HTTP 403). 2026-10-14 수동 실행에서 확인했다.

### 사용자 추가가 `This user still has a personal balance or subscription`으로 거부됨

추가하려는 사용자에게 개인 잔액(quota > 0)이나 활성 개인 구독이 남아 있다(6장). 사용자가 잔액을 소진하거나 구독이 만료·취소되면 추가할 수 있다. 바로 넣어야 하면 전체 관리자가 사용자 관리에서 그 사용자의 잔액을 0으로 바꾸고 개인 구독을 취소한다.

### 플랜 삭제 후에도 사용자가 남아 보임

확인 사항:

- 취소된 구독은 기본 할당 목록에서 숨겨진다.
- 브라우저를 새로고침하거나 목록을 다시 조회한다.
- active 구독이 남아 있으면 취소 버튼을 다시 누른다.

### 지갑에 개인 잔액이 보이지 않음

조직 구독 플랜이 할당된 사용자는 정상 동작이다. 개인 잔액 대신 `Organization plan in use`가 표시된다.

### `default`가 표시됨

한국어 locale이 들어오기 전(단계 D)까지는 그룹 badge가 `default`로 표시된다. 정상이다.

## 19. 운영 팁

- 조직 quota는 조직 전체 예산이다. 사용자별 quota나 구독 한도보다 먼저 충분히 확보해야 한다.
- 조직 구독은 사용자별 한도를 명확히 관리하고 싶을 때 사용한다.
- 일회성 또는 단순 제한은 사용자 quota 방식이 더 간단하다.
- 조직 구독 플랜 사용자는 개인 지갑 충전 흐름을 사용하지 않는다.
- 조직 사용량 문제를 확인할 때는 조직 대시보드, 조직 사용 로그, 지갑 화면을 함께 확인한다.
