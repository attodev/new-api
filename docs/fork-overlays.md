병합 처리: upstream이 이 파일을 고치면 `modify/delete` 충돌이 난다. 해결은 삭제를 유지하는 것이다 — `git rm <file>`. upstream이 `en.json`에 키를 더한 경우는 위 공통 (i18n) 행대로 `bun run i18n:sync`가 en/ko만 갱신한다(sync는 디렉터리에 있는 파일만 읽으므로 지운 locale을 다시 만들지 않는다). upstream이 새 테스트에서 `@/i18n/locales/{zh,zh-TW,fr,ja,ru,vi}.json`을 import하면 `bun run test`가 import 오류로 실패한다 — 위 "en/ko 축소 (테스트)" 행처럼 `ko.json`과 한국어 기대값으로 바꾼다. 2026-10-15 단계 E 리허설(qn/main 718a4e7f9): develop이 지운 프런트 locale 6개(`fr`, `ja`, `ru`, `vi`, `zh-TW`, `zh`)를 upstream이 고쳐 `CONFLICT (modify/delete)` 6건이 났고, `git rm web/src/i18n/locales/{fr,ja,ru,vi,zh-TW,zh}.json`으로 모두 풀렸다(yaml 2개는 upstream이 건드리지 않아 충돌 없음). 콘텐츠 언어(`features/task-plugins/lib/plugin-changelog.ts`, `features/models/types.ts`의 `SyncLocale`, `features/models/constants.ts`의 `Japanese`, `lib/localized-text.ts`의 `zhcn`→`zh-cn` 매핑)와 `README.*.md` 번역본은 화면 언어가 아니라 지우지 않는다. `web/scripts/sync-i18n.mjs:229-236`의 `ja/zh/ru/fr/vi` 분기는 해당 파일이 없으면 실행되지 않으므로 충돌면을 줄이려고 그대로 둔다.
